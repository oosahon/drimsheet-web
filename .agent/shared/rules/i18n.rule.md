# i18n Rules

## Translation Keys

- Use `snake_case` for all translation keys within the JSON locale files.

## Namespaces

- Create translations based on domains, meaning each domain should have its own JSON file (e.g., `<domain>.json` such as `auth.json`, `onboarding.json`).

NB:
Every top-level directory in the `src` is a domain. Non-domain top-level directories are prefixed with `_` (e.g., `_app_`,)

## React Components Usage

- Texts should be easily visible. Instead of using `t()` directly inside React elements, you must extract the translated text into a variable at the top of the component or render function.
- **Variable Naming:** Extracted variables should follow the `snake_case_text` convention to clearly identify them as translation strings (e.g., `or_text`, `no_account_text`).

**Incorrect:**

```tsx
<FieldSeparator>{t('common:or')}</FieldSeparator>
```

**Correct:**

```tsx
const or_text = t('common:or');

// ...
<FieldSeparator>{or_text}</FieldSeparator>;
```
